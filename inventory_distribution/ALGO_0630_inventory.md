# 06:30 GP 库存与容量求解说明

对应脚本：`estimate_0630_inventory.py`  
输出：`out/gp_0630_inventory.csv`（`gp, m_i, w_i, I0_0630, q_i, short_days`）

## 1. 符号

| 符号 | 含义 | 定义 |
|---|---|---|
| `i` | GP 编号 | `hw6_grid_ownership.csv` 中的 90 个非 `UNASSIGNED` 的 `gp` |
| `t` | 早高峰时间槽 | `t = ⌊(分钟数 − 390) / 30⌋`，`390` = 06:30；`t = 0..7` 对应 8 个半小时 |
| `s` | 累计求最大时的槽下标 | `s = 0..7` |
| `D_i(t)` | GP `i` 在槽 `t` 的离开数 | `start_time ∈ [06:30+30t, 06:30+30(t+1))` 且 `start_geohash` 属于 GP `i` 的订单数 |
| `A_i(t)` | GP `i` 在槽 `t` 的到达数 | `end_time` 落在槽 `t` 且 `end_geohash` 属于 GP `i` 的订单数 |
| `cumD_i(s)` | 截至槽 `s` 的累计离开 | `Σ_{t=0..s} D_i(t)` |
| `cumA_i(s)` | 截至槽 `s` 的累计到达 | `Σ_{t=0..s} A_i(t)` |
| `m_i` | 库存下界 | 见 §2.1；单位：辆 |
| `w_i` | 空间先验权重 | 见 §2.2；`Σ_i w_i = 1` |
| `N` | 06:30 停在 90 个 GP 的总车数 | 标量；默认 `N = Σ_i m_i` |
| `N_min` | 最小可行总车数 | `N_min = Σ_i m_i` |
| `a_i` | 先验目标值 | `a_i = N·w_i`，即先验认为 GP `i` 应有多少辆 |
| `I_i` | 06:30 的 GP 初始库存（求解对象） | 输出列 `I0_0630` |
| `q_i` | GP 容量（求解对象） | 见 §2.5；单位：辆 |
| `r` | 投影的统一缩放因子 | `r = 1 + λ`，`λ` 为总量约束的拉格朗日乘子 |
| `k` | 被下界 `m_i` 顶住的 GP 数 | `0 ≤ k ≤ 90` |
| `d` | 工作日日期 | 见 §2.0 |
| `short_days_i` | GP `i` 出现负库存的工作日数 | 诊断量，见 §2.6 |

**时间口径约定（保守版）**：槽 `t` 内到达的车只能从 `t+1` 起被使用，因此库存递推为
`I_i(t+1) = I_i(t) + A_i(t) − D_i(t)`，且要求 `I_i(t) − D_i(t) ≥ 0`。

## 2. 算法设计

### 2.0 数据与样本

- **空间**：只统计分配给 90 个 GP 的 5,630 个 L8 格点；`UNASSIGNED` 格点不进入 GP 库存。
- **工作日**：周一至周五，剔除 8 个法定节假日，加入 2026-05-09 调休。
- **样本**：2026-03-02 至 2026-05-21 共 **56 天**；2026-05-22 是半天数据，直接排除。

### 2.1 下界 `m_i`

对每个 GP、每个工作日 `d`：

```text
m_i(d) = max_{s=0..7} [ cumD_i(s) − cumA_i(s−1) ]⁺,   cumA_i(−1) = 0
m_i    = mean_d m_i(d)
```

- 含义：在不调度、不缺车的前提下，06:30 至少要有多少辆。
- 参数确定：逐日计算后对 56 个工作日取平均，得到“平均工作日”的下界。
- 若某天流量更大，`m_i(d)` 会高于均值，由 `short_days` 标记。

### 2.2 先验 `w_i`

目标日 `d` 的晚间先验窗口定义为 **昨日 22:00 至次日 06:00**：晚间部分取**上一个工作日** `p(d)` 的 22:00–24:00，凌晨部分取**目标日 `d` 自己**的 00:00–06:00：

```text
evening(d) = [p(d) 22:00, p(d) 24:00) ∪ [d 00:00, d 06:00)
raw_i(d)   = max(0, A_i^evening(d) − D_i^evening(d))
```

- 含义：06:30 的车主要来自前一晚 22:00 之后停进来的车，加上当日凌晨的少量净流入。
- **周一**：`p(d)` 自动回退到上周五，窗口为**周五 22:00–24:00 + 周一 00:00–06:00**；周六、周日的流量（包括周末凌晨）不进入先验。
- 节假日后：同样取上一个工作日 `p(d)` 的 22:00–24:00 加目标日 `d` 的 00:00–06:00。
- 若某个目标日所有 `raw_i = 0`，退回用该窗口的到达 `A_i^evening(d)`。
- 对所有可用目标日的 `raw_i(d)` **按计数求和**后归一化：

```text
w_i = Σ_d raw_i(d) / Σ_j Σ_d raw_j(d)
```

- 其中 `A_i^evening(d)` 按 `end_time` 落窗且 `end_gp = i` 计数，`D_i^evening(d)` 按 `start_time` 落窗且 `start_gp = i` 计数；只要一端落在 GP `i` 就计入，不要求另一端也在 GP。
- 注意：`max(0, ·)` 是**逐目标日**取的，某个目标日的负净流出不会抵消另一天的正净流入。因此 `w_i` 表示“夜间经常积累车辆的 GP”，不是 56 天的平均净流入。
- 参数确定：晚间窗口固定为 `p(d)` 22:00–24:00 + `d` 00:00–06:00；首日 2026-03-02（周一）在数据中没有上一个工作日，自动丢弃（实际使用 55 个目标日窗口）。

### 2.3 总车数 `N`

- 默认：`N = N_min = Σ_i m_i`，即“刚好不出现缺车”的最小总量。
- 可选：若能从车队记录得到 06:30 停在 GP 的总车数，用 `--n` 传入。
- 校验：必须满足 `N ≥ Σ_i m_i`，否则直接报不可行。
- **重要推论**：默认 `N = N_min` 时所有下界同时生效，`I_i = m_i`，所以 `w_i` 不会改变 `I_i`、`q_i` 或 `short_days`；只有传入 `--n > N_min` 时，`w_i` 才参与库存分配。

### 2.4 投影求 `I_i`

求解可分凸二次规划：

```text
minimize   Σ_i (I_i − a_i)² / (2·a_i),   a_i = N·w_i
subject to I_i ≥ m_i
           Σ_i I_i = N
```

**解析解（water-filling）**：由 KKT 条件，未触界的 GP 取 `I_i = a_i·r`，触界的取 `I_i = m_i`。

1. 按 `m_i / a_i` 从大到小排序，记为 `m_(1..90)`、`a_(1..90)`。
2. 对 `k = 0..90`，令

```text
r_k = (N − Σ_{j≤k} m_(j)) / (N − Σ_{j≤k} a_(j))
```

3. 取第一个满足 `m_(k) / a_(k) ≥ r_k ≥ m_(k+1) / a_(k+1)` 的 `k`。
4. 前 `k` 个 GP 取 `m_i`，其余取 `a_i·r_k`。

此时自动满足 `Σ_i I_i = N` 和 `I_i ≥ m_i`。若 `N = N_min`，所有 GP 都触界，`I_i = m_i`。

### 2.5 容量 `q_i`

对每个工作日 `d`，用求得的 `I_i` 作为 `t=0` 起点，按库存递推得到整段早高峰轨迹：

```text
I_i(d, 0)   = I_i
I_i(d, t+1) = I_i(d, t) + A_i(d,t) − D_i(d,t)
```

定义：

```text
q_i = ceil( max_{d, t=0..8} I_i(d, t) )
```

- 含义：**观测到的早高峰中从不溢出**所需的最小容量，是物理容量的下界。
- 参数确定：对所有 56 个工作日、9 个时刻点取峰值，再向上取整。
- 注意：`q_i` 依赖 `I_i` 和 `N`；OD 数据本身无法识别真实物理容量。

### 2.6 诊断 `short_days_i`

```text
short_days_i = # { d : ∃ t,  I_i(d,t) − D_i(d,t) < 0 }
```

表示在固定的 `I_i(06:30)` 下，该 GP 在多少个工作日的早高峰会出现缺车。它不是求解目标，只用于判断单一初始库存是否足够；数值大说明需要调度或逐日估计。

### 2.7 数值细节

- 先验中的 0 权重用 `1e-9` 替代后重新归一化，避免除零；这类 GP 会被投影到下界 `m_i`。
- 所有库存量在中间计算中保留浮点，容量 `q_i` 最后向上取整为整数。

### 3.4 关键：默认参数下 `w_i` 不改变 `I0/q`

默认 `N = N_min` 时，投影的 90 个下界全部生效，`I_i = m_i`。因此：

- 本次对 `w_i` 定义的修改**不会改变** `I0_0630`、`q_i`、`short_days`；
- 它只会改变输出中的 `w_i` 列；
- 只有传入 `--n > N_min` 时，`w_i` 才会决定“多出来的车分给谁”。

- 逐日总下界 `Σm_i(d)` 的均值为 1,189.9、标准差 159.7、p95 为 1,361、
  最大 1,366（约 +15%）、最小 619。也就是说：**总量层面的日间上侧压力只有
  约 15%**；但单个 GP 的日峰值/均值中位数为 2.82×、p90 为 9.3×（小流量 GP
  占多数），所以即使总量够，局部也会缺车。`short_days` 高主要来自空间分布
  对不上，而不是总量在峰值日翻倍；这一点在解释“无调度假设”时很重要。

### 3.7 与 GP 流向分析的联动

本节用到的流向符号（来自 `flow_balance_gp.py`）：

| 符号 | 含义 |
|---|---|
| `dep_day` | GP `i` 平均每个工作日作为起点的 GP→GP 单数 |
| `arr_day` | GP `i` 平均每个工作日作为终点的 GP→GP 单数 |
| `net_day` | `dep_day - arr_day`；`> 0` 为源点，`< 0` 为汇点 |
| `b_out` / `b_in` | GP 池 → 非 GP / 非 GP → GP 池的平均单数/日 |
| 毛失衡 | `Σ_i max(net_day_i, 0)`，即所有源点净流出之和 |

来自 `flow_balance_gp.py`（56 个工作日、`[06:30, 10:30)`）：

| 指标 | 数值 |
|---|---:|
| GP → GP 行程 | 79,208 单，1,414.4 单/日 |
| 占早高峰行程 | 约 49.6% |
| 源点 / 汇点 GP | 42 / 48（按平均净流） |
| 毛失衡 `Σ max(net, 0)` | 835.9 辆/日，占 GP→GP 的 59.1% |
| 边界骑出 / 骑入 | 557.6 / 596.6 单/日 |
| 边界净流入 | +38.9 单/日，47/56 天为正，in/out = 1.070 |

- 前 5 大源点：H6GP016 +343.6、H6GP052 +73.4、H6GP047 +63.5、
  H6GP011 +41.0、H6GP048 +28.7，合计 550.2 辆/日（占全部源点平均净流出的 67.5%）。
- 前 5 大汇点：H6GP033 -70.3、H6GP020 -63.0、H6GP012 -50.8、
  H6GP017 -46.1、H6GP040 -44.9，合计 275.0 辆/日（占全部汇点平均净流入的 33.8%）。
- 解读：早高峰的失衡**主要是 GP 之间的再分配**；GP 池与非 GP 端点的净交换
  只有 +38.9 单/日，相对 1,414 单/日的 GP→GP 流量很小。
- 口径注意：这里的“边界”是 **GP 已分配格点 <-> 所有非 GP 端点**，非 GP 端点
  既包括核心区内 4,843 个 `UNASSIGNED` 格点，也包括核心区外的格点；
  它**不是** `data_select_configure_zgc_20260909.xlsx` 蓝色研究区环的内外穿越。
  不要把它和 `flow_balance.py` 的“核心区（10,473 格点）边界”直接对比；
  后者用 57 个工作日，且核心区定义不同。

### 3.8 结论的边界（答辩时建议主动说明）

1. **水平不可识别**：OD 只能约束库存变化，不能唯一确定 06:30 的绝对水平；
   默认 `N = N_min` 给出的是“最小可行基线”，不是实际库存。
2. **`q_i` 是下界**：它是“观测到的早高峰不溢出”的最小值，依赖 `I_i` 和
   无调度假设；不能当作真实站点容量。
3. **无动态调度**：`m_i` 是 56 天逐日均值；`short_days` 说明单靠这个静态向量
   不能覆盖每天。若做逐日调度，需要把 `m_i(d)` 或调度量加入约束。
4. **保守时间口径**：槽 `t` 内到达的车从 `t+1` 才可用，因此 `m_i` 略高于
   “到达即可用”的口径。
5. **`w_i` 口径**：逐目标日取正部后求和；周一/节假日后跳过周末；4 个 GP 权重为 0；
   2026-03-02 因没有前序工作日被丢弃。
6. **样本范围**：2026-03-02 至 2026-05-21 的 56 个工作日；2026-05-22 半天数据排除；
   结论不外推到其他季节或大型活动日。
7. **边界口径**：GP 流向脚本的 boundary 是 GP 集合与所有非 GP 端点之间，
   不是 xlsx 研究区环的穿越流量。
8. **可校准方向**：若能用 `bike_id` 串起连续行程或拿到车队 06:30 盘点，
   可以估计真实 `N`，再用 `--n` 重新投影；这是把“基线”变成“实际值”的关键。

### 4.3 三句话结论（可直接作为讲稿）

1. **总量**：90 个 GP 的 06:30 最小可行库存是 **1,190 辆**，前 5 个 GP 占 54.2%，
   H6GP016 一个占 33.8%——库存问题本质上是少数源点的供给问题。
2. **结构**：源点持有 92.4% 的库存却只需要 42.7% 的容量；汇点只有 7.6% 的库存
   却需要 57.3% 的容量——库存和容量在空间上是错位的。
3. **风险**：单一静态库存向量在 90/90 个 GP 上都至少有一天缺车，平均 22.6/56 天；
   总量层面的峰值压力仅约 +15%，说明主要矛盾是空间分布，而不是总车数。

> 注意：默认 `N = N_min` 时 `w_i` 不影响结果；如果 PPT 要讲先验的作用，
> 用 `N = 1.25×/1.5× N_min` 的情景图，不要把它包装成默认结果。

### 4.4 预答问题

- **为什么 `I0` 全等于 `m_i`？** 默认 `N = N_min`，所有下界同时生效；有真实
  总车数时用 `--n`。
- **为什么改了 `w_i` 结果没变？** 同上；`w_i` 只在 `N > N_min` 时分配多余车辆。
- **`q_i` 为什么比 `I0` 大很多？** 汇点早高峰持续到达，库存累积；`q_i` 是
  不溢出的最小容量，且未考虑中途调度。
- **为什么不用 `w_i` 直接当库存？** 先验只描述空间比例，不满足非负约束，
  也不能识别水平；`m_i` 是硬下界。
- **56 天不调度是否过强？** 对单个 GP 很强（`short_days` 平均 22.6 天），
  但逐日总下界只比均值高约 15%，说明总量层面可承受，局部需要调度/缓冲。
- **边界流为什么不是 1.199？** `flow_balance.py` 的核心区是 10,473 个格点、
  57 个工作日；`flow_balance_gp.py` 的边界是 GP 集合与非 GP 端点、56 个工作日，
  两者口径不同。
